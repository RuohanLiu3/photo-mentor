# 取景 FRAME 手机产品框架实施方案

日期：2026 年 9 月 27 日。版本：0.4，非 AI 框架包含器材推荐与具体机型模拟页面。

本文件保留用户确认的 v0.4 实施范围与验收要求。当前已经沿用现有网站完成本地代码实施：首页、准备、指导、调整、对比、学习、器材推荐、具体机型模拟页面和本机记录能够连贯体验；画面与摄影建议使用明确标注的内置示例。具体已验证内容与限制见[实施与验证状态](IMPLEMENTATION_STATUS.md)。之后分步接入手机摄像头和真实 AI 分析。

产品定位保持为：手机观察现场，AI 提供摄影指导，用户最终用手机或相机拍摄。本轮不接摄像头、不调用模型、不连接相机、不开发硬件。当前交付已从方案推进为本地可交互框架；本轮没有提交、推送或部署，也未将桌面浏览器窄视口检查当作实体手机验收。

本版阶段顺序与获确认的功能边界以本文件为准；项目原有产品与接口文档可继续作为参考。下文工期保留为实施前的历史估算，不表示实际耗时、剩余工期或已经完成全部验收。

**本阶段要交付的结果**

用户可以用手机打开网站，不注册、不授权摄像头，完成下面的示例体验：

> 首页开始体验 → 选择最终拍摄设备与目标 → 可选风格参考 → 进入示例取景工作区 → 查看一个动作 → 选择调整后的示例画面 → 检查变化 → A/B 对比 → 记录偏好 → 在本机记录中再次查看。

每个环节都能返回、修改与继续。照片来源、建议来源和比较结果始终保留“内置示例”身份。真实操作包括目标选择、页面导航、参数模拟、参考卡展开、辅助线开关、缩放、偏好保存与历史读取；示例结果不被表述为 AI 对用户现场的判断。

本阶段完成可证明页面和流程可用，不能证明摄像头兼容性、真实 AI 质量、现场改善或付费需求。

拍摄方式描述为“最终用手机拍／最终用相机拍”。两种方式都围绕手机观察现场设计，相机模式本期可以体验手工填写设备信息与不同建议表达，但所有摄影判断仍来自固定示例。

首页正式接入摄像头前用“开始体验”，工作区明确显示“示例模式”。不显示已经开启摄像头、正在分析现场或已经云同步等不真实状态。

**器材推荐和具体机型模拟的页面范围**

器材推荐的流程为：需求问卷 → 推荐组合 → 查看详情或对比 → 收藏 → 进入相关模拟练习。问卷收集预算与币种、题材、便携需求、经验、视频需求及已有器材，支持返回修改并保留输入。问卷不要求用户知道喜欢哪个品牌，也不把照片风格直接等同相机品牌。

推荐页以机身加镜头的组合呈现，统一说明适合什么、牺牲什么、预算如何分配。首轮使用少量明确标注的演示套装验证筛选、比较和收藏，不给虚构的真实机型参数或现价。真实目录接入时，每项参数、兼容性和价格应有来源；价格另外记录币种、地区与更新时间，未知内容不补猜。

比较页在手机上按同一维度分组展示两到三套组合，避免宽表格迫使用户横向滚动。选中套装可以带入模拟器，或者加入收藏；只有用户明确选择“加入我的器材”才记录为已拥有，收藏和推荐结果不自动变成用户设备。

具体机型模拟页面预留完整的操作位置：顶部机型选择和当前模式，中部场景预览与可切换的机身视图，底部参数控件与按键讲解。手机默认只显示当前任务需要的控件，其他控件通过分组展开；同时提供自由体验与跟着任务练习。

首轮用一套完整通用教学配置验证按键热点、参数联动、讲解、任务与重置。真实型号只有在说明书和行为校对后才标为可用；未覆盖型号提供明确状态和通用练习入口。页面结构完整与所有型号的精确模拟是两个不同的交付范围。本轮包含前者；每个真实型号的校准与完整性以后逐项验收。

**让各模块互通的产品建议**

1. 手机主导航控制为五项：首页、拍摄、学习、器材、我的。机型模拟从学习和器材详情都能进入；风格参考在学习及拍摄准备中出现，不再挤占一个底部导航位置。
2. 建立一个本机偏好和器材档案，保存常用拍摄方式、已有机身与镜头、收藏和最近练习。进入拍摄或模拟时可带入，也能仅修改本次设置，不要求重复填表。
3. 打通“器材推荐 → 对比 → 模拟操作 → 收藏或加入我的器材 → 去拍摄”，以及“课程 → 模拟练习 → 带着本次目标去拍摄”。用户不需要先购买设备或完成课程才能进入指导。
4. 自由体验与任务练习共用模拟器。任务从现有曝光、景深和构图课程中选取，先复用内容；参数拖动后即时反馈，解释按需展开，避免同时堆满控制项和术语。
5. 机型资料、按钮位置、参数范围、模式规则和教学说明采用独立配置。页面和通用教学规则尽量复用，以便以后逐台增加机型，避免为每台机器重新写整页界面。通用模拟不声称复现特定机型画质。
6. 开发前先画清页面关系与返回路径，第一批预览同时检查拍摄工作区、器材结果和机型模拟的手机布局。每个页面都应有明确下一步、返回路径，以及缺少内容时仍能继续的入口。

**实施前代码基础与本轮重构**

实施前项目已有 React、TypeScript、Vite、三节互动练习、示例指导、个人图片预览、方法卡和本机记录，大部分页面集中在 `src/App.tsx`。本轮保留 `src/domain.ts` 的教学规则及 `src/storage.ts` 的历史记录兼容逻辑，将页面拆分到 `src/pages/`，并增加独立的指导、器材、模拟器及档案数据模块。

实施前照片、步骤和本轮判断主要位于 `Coach` 内部，页面卸载后无法完整恢复。本轮已把内置示例会话移到应用上层并独立持久化，用结果身份和上下文版本避免迟到响应覆盖新的选择；个人图片仍只作临时本机预览。

保留原有 URL 的可访问性或提供明确兼容映射，避免已分享的现场指导链接失效。原有课程和记录按版本兼容读取，不能因为换界面就清空用户已保存内容。

已有个人图片预览与手动比较可保留，但不套用内置场景建议。个人图片刷新后如无法恢复，明确提示重新选择，不把过期图片链接当成可用图片。

**先定义最小接口，暂不建设完整后端**

界面读取统一的画面和建议结构。本期由内置场景实现这些接口；后续增加摄像头来源和服务端分析实现。目标是让页面少依赖数据来源，而不是承诺接入时完全不用调整。

| 职责 | 本期实现 | 后续实现与约束 |
| --- | --- | --- |
| 画面来源 | 读取内置前后示例图，返回帧 ID、尺寸、方向和来源 | 摄像头实现提供预览与采样；启停、权限与中断需要独立实机验收 |
| 指导来源 | 返回与选定示例、目标和限制匹配的预设动作与标记 | 后端分析实现返回同一基本结构，补充超时、拒绝、限额及无法判断状态 |
| 比较来源 | 根据明确的前后示例与目标返回人工编写的变化 | 真实比较只能引用对应的手机帧或相机成片 |
| 本机记录 | 保存目标、步骤、示例资产 ID、用户选择和规则练习记录 | 以后增加云端实现与迁移，本期不建设账号数据库 |
| 器材与机型资料 | 带版本和演示标记的本地套装数据、机型配置和本机档案；使用稳定 ID 关联推荐、模拟与收藏 | 经核实的实际器材目录与机型操作配置，保留来源及更新时间 |

建议每个结果携带：`sessionId`、`frameId`、`contextVersion`、`sourceKind`、当前状态和必要的错误信息。摄影建议包含观察、区域、一个主要动作、原因、条件及下一步检查。

目标、风格、设备或画面改变后，增加上下文版本。旧建议可以作为历史保留，但不能在新画面上继续显示成当前结论；迟到的旧响应必须被丢弃。辅助框坐标对应具体帧，缩放和留白时正确变换。

预留分析接口的取消或忽略旧结果能力。本期用延迟的示例响应验证，之后接真实网络时仍需完整测试。API 密钥、服务器预算和上传权限在真实 AI 阶段实现；本期只定义必需的契约，不建立一套闲置服务。

**把会话和异常流程一起搭好**

主流程建议为：

> 准备 → 画面就绪 → 等待示例建议 → 建议可查看 → 用户尝试调整 → 调整后画面就绪 → 比较 → 已记录。

等待可以取消，失败可以重试，画面不可用时可以换来源。用户可随时返回准备页改目标，但相关建议要失效或重新生成。点击“调整好了”仅记录用户的动作声明，不直接写入“改善成功”。

开发侧提供固定场景来检查：正常返回、延迟返回、失败重试、没有可靠建议、没有明显变化、用户更喜欢原图，以及修改目标后旧结果才返回。摄像头权限拒绝与预览中断可以先用测试状态检查页面承接方式，不触发真实设备权限；这不算硬件兼容测试。

这些状态选择放在开发环境的测试入口，普通用户界面只显示自然的解释和下一步操作，不暴露接口或调试术语。

**进度和存储的明确范围**

本期确保内置示例体验在页面切换与刷新后可恢复：存储可重建的示例资产 ID、拍摄方式、目标、风格、步骤和结果版本。图片数据不写入现有 localStorage 摘要，预览 URL 也不作为长期记录。

用户主动清除本机数据后，应显示真实空状态。存储不可用或空间不足时，当前会话仍可继续，但明确说明这次未能持久保存。跨设备恢复、私人照片长期保存与账号迁移不作为本期验收条件。

**本期不扩展的内容**

账号、支付、订阅、云作品库、完整真实器材与价格数据库、全部具体型号的精确模拟，以及自动分析和实时标记跟踪，留待对应阶段。器材推荐和具体机型模拟的入口、完整页面及上述交互已经纳入本期范围；真实数据规模与型号校准不计入页面框架的完成度。

现有三节参数练习可以真实改善，因为它们使用本地规则，不依赖 AI。先做到控件顺畅、规则可解释和示例一致；更多场景不占用主流程的交付时间。

**分批实施顺序与历史估算**

以下是用户确认方案时的实施前估算，按一名熟悉当前前端项目的开发者、AI 辅助开发、沿用已有素材和教学内容计算。工作日表示当时预估的工程量，不是实际耗时、剩余工作量或已经验证的交付日期；当前进度与证据另见实施状态文档。

| 批次 | 主要工作 | 可检查的交付物 | 估算 |
| --- | --- | --- | --- |
| 1 基础结构 | 拆分页面和共用组件、统一手机布局、定义最小会话及数据契约、接入内置数据来源 | 首页进入工作区，修改准备信息后返回仍保留；现有学习入口可用 | 1–2 个工作日 |
| 2 拍摄完整流程 | 准备、可选参考、示例建议、辅助标记、逐步动作、调整检查、A/B 对比和保存 | 至少三组动作与前后变化相互对应的示例，从入口到记录可走完 | 2–3 个工作日 |
| 3 器材与机型页面 | 需求问卷、演示套装、详情对比收藏、机型选择与操作布局、一套通用配置、跨页面信息传递 | 从器材推荐进入模拟练习，返回后保留问卷和选择；收藏与已有器材分开 | 3–5 个工作日 |
| 4 学习与记录整合 | 现有课程、参数控件、方法卡、本机器材档案与记录、未完成会话继续、兼容旧记录 | 学习、模拟、器材与指导能互相进入，刷新可恢复内置示例进度 | 2–3 个工作日 |
| 5 验收与修正 | 手机浏览器交互、横竖屏、失败及旧响应、存储、回归、可访问性与构建检查 | 可分享的框架预览版本与明确的验收记录 | 1–2 个工作日 |

当时增加器材推荐和具体机型模拟页面后的历史估算总计约 9–15 个工作日，即 2–3 周；其中新增两块估计增加 3–5 个工作日。该估算不包含大规模真实机型资料校准、新增大量课程、制作介绍视频或真实摄像头与 AI 接入，也不应被解读为本轮实际消耗了这些时间。

获确认的实施顺序从“页面结构与拍摄会话”开始，再打通准备、指导、对比、记录，并加入器材与模拟页面。当前这些部分已有本地实现，后续修改仍以完整流程和对应验收证据为依据。

**框架验收标准**

| 检查 | 通过条件 |
| --- | --- |
| 全流程 | 不登录、不调用摄像头、不访问 AI 服务，也能走完示例指导、对比和本机保存。 |
| 真实性 | 画面、建议与历史记录均保留来源；示例模式不会被描述成现场分析。 |
| 一致性 | 每个动作都对应正确示例和变化说明；“没有改善”及“更喜欢原图”可以记录。 |
| 导航与恢复 | 返回、查看参考和刷新后，内置示例的目标、步骤及记录可正确恢复。 |
| 器材推荐 | 问卷可修改，示例筛选与解释一致；对比及收藏可用，未提供真实现价时不显示成实时价格。 |
| 机型页面 | 一套通用配置可完成选择、按键讲解、参数调整、任务及重置；未校对型号不被标为精确模拟。 |
| 模块互通 | 推荐、模拟、我的器材与拍摄共享同一设备 ID；收藏不自动写成已拥有；本次设置覆盖不会静默修改常用档案。 |
| 异步边界 | 修改目标或图片后旧结果不覆盖当前上下文；失败重试不重复记录。 |
| 标注与对比 | 横竖画面和缩放下框的位置正确；同步缩放可重置，不假装不同构图像素完全对齐。 |
| 存储 | 兼容已有记录；损坏数据、无法写入和主动清除都有可理解的处理。 |
| 手机操作 | 真实手机浏览器可点、可拖、可返回；窄屏无横向溢出，横屏及键盘操作可用。该检查不证明摄像头兼容。 |
| 工程回归 | 原有测试、类型及生产构建、格式检查通过；对会话恢复、过期响应和存储迁移增加必要的行为测试。 |

验收不以页面数量或按钮数量计算。要求主流程完整、状态真实、返回不丢进度，并且未来接入所需的数据边界明确。

**框架完成后的接入顺序**

第一步接手机摄像头，只替换画面来源：验证权限、后置预览、采样、启停、横竖屏和后台恢复。手机实时画面此时不自动套用示例建议；需要体验示例时明确切回内置场景。

第二步接真实 AI 后端：增加上传、会话权限、密钥管理、费用上限、结果校验及失败恢复，在明确支持的场景中提供真实建议。先按用户触发分析，质量和延迟通过检查后再考虑自动采样。

第三步完善手机辅助相机：沿用本期的模式和器材信息入口，接入经过验证的相机建议，允许用户主动导入实际成片复盘。手机观察与相机成片始终分开记录。

以上接入阶段需要独立估算与真实测试。框架做完可以减少界面返工，但不能替代对模型质量、浏览器差异、拍摄质量和现场操作的验证。
