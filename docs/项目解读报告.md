# 取景 FRAME 项目解读报告

本报告依据当前工作目录中的 47 个原有文件整理。检查涵盖业务代码、页面、组件、测试、产品文档、样式、依赖锁文件及发布配置；业务代码与文档作内容核对，样式和依赖锁文件作结构检查。本次另行运行了全部 78 项现有测试，全部通过。未修改产品代码。

## 1. 这个项目在做什么

**取景 FRAME 是一个面向手机使用的摄影教学与拍摄指导网站，当前版本为 0.4.0。** 它希望帮助用户理解摄影参数、在拍摄时尝试一个具体调整，再通过前后对比判断这个调整是否符合自己的表达目标。

产品面向手机拍照初学者、相机新手，以及希望探索不同拍法的摄影爱好者。长期设想是：手机观察现场，AI 给出指导，用户最终使用手机或相机拍摄。

**当前已经交付的是可交互的前端体验框架。** 参数教学、本机记录、器材筛选、页面互通和手动照片对比有实际逻辑；现场画面和摄影建议来自预先编写的示例。真实摄像头、AI 图像理解和服务端尚未实现。

项目名称中虽然有 scaffold（脚手架），目录已经包含完整页面与业务规则，不能把它理解为仅有空页面的初始模板。

## 2. 用户可以怎样使用

主要导航有五项：首页、拍摄、学习、器材、我的。另有相机模拟器、摄影方法卡、个人照片对比和三节独立课程，共 11 个有效页面路径。

| 模块 | 当前实际行为 | 能力边界 |
| --- | --- | --- |
| 首页 | 展示构图前后变化，开始或继续拍摄体验，进入学习、模拟器及器材页 | 首页示意来自程序绘制的场景 |
| 拍摄 | 选择设备、目标、场景、风格和现场限制；查看动作；选择调整结果；比较并保存偏好 | 三组内置示例，没有观察真实现场 |
| 学习 | 曝光与运动、景深与主体、构图与背景三课；调整参数、查看提示、检查结果、恢复进度 | 依照本地规则判断特定练习目标，没有 AI 教师对话 |
| 器材 | 填写预算、题材、便携性、经验、视频需求；排序、查看详情、最多比较三套、收藏或加入已有器材 | 只有四套虚构教学组合，金额不是真实价格 |
| 相机模拟器 | M 手动、A 光圈优先、S 快门优先；参数联动、三面机身热点、自由体验和任务练习 | 只有一套通用配置，未精确支持真实品牌型号 |
| 个人照片对比 | 选择两张本机图片，并排或切换观察，同步缩放和调整观察位置，保存偏好及原因 | 不分析照片，不自动对齐，不保存照片原文件 |
| 我的 | 常用拍摄方式、机身镜头、收藏、已有套装、课程提交、最近 20 条对比判断及清除入口 | 数据只在当前浏览器，没有账号和跨设备同步 |

### 拍摄主流程

首页 → 拍摄准备 → 示例画面 → 查看一个主要动作 → 选择调整后的示例或保持原样 → 前后比较 → 保存偏好和原因。

三组场景分别处理：街角人像的背景线条重叠、旅行人像中人物与环境的取舍、窗边人像的面部受光。选择“机位不能移动”或“人物不能调整”会影响建议；用户也可以查看理由、替代方案和下一步观察点。

系统允许记录“更喜欢原图”“两张各有优点”“没有明显变化”和“暂时无法判断”。这体现了项目的重要产品原则：评价围绕用户的拍摄意图，不把调整后自动视为更好。

### 各模块怎样衔接

- 课程可以把表达目标带入拍摄示例，也可以在模拟器里继续练习。
- 器材组合可以带入模拟器和拍摄准备；四套组合使用同一套通用模拟规则。
- 收藏与已有器材分别管理，收藏不会自动变成“已经拥有”。
- 常用档案可以主动带入本次拍摄；临时体验某套器材不会直接覆盖常用档案。

## 3. 界面背后的工作原理

### 摄影指导来自预设规则

`coaching.ts` 根据场景、目标、限制和参考方法选择预编写动作，再返回对应的观察、理由、代价和检查点。比较说明也与固定的前后示例对应。

“正在加载示例”通常是约 450 毫秒的本地延迟，用于呈现和测试异步流程。开发环境还提供慢响应、失败、无法给出可靠建议和没有变化等测试状态。这些等待状态不代表正在调用远程模型。

### 模拟器有真实计算逻辑，但画面是教学近似

曝光计算以 1/125 秒、f/4、ISO 200 为参考点，计算快门、光圈和 ISO 的相对亮度变化。A 模式在已有档位中选择快门，S 模式选择光圈，使结果尽量接近目标亮度；ISO 保持手动。

课程中的拖影、背景模糊、噪点和构图通过 SVG 场景变化表现。它适合讲解参数关系，不是完整光学仿真，也不预测某台真实相机的成片。

### 记录围绕实际操作

学习记录保留提交次数、是否曾达到本题目标、是否使用过提示。对相同设置连续点击检查不会重复增加提交次数。代码明确区分“本题达标”和“掌握实拍能力”。

## 4. 技术结构与数据保存

| 层次 | 当前选择 | 对项目的意义 |
| --- | --- | --- |
| 界面 | React + TypeScript | 页面和交互组件；类型检查帮助约束数据 |
| 构建 | Vite | 生成可静态托管的网站文件 |
| 样式与图示 | 六份 CSS、SVG 场景、Lucide 图标 | 响应式布局与程序绘制的教学素材 |
| 路由 | 浏览器 hash 路由 | 使用 `#/coach` 等地址，适合静态站点 |
| 共享状态 | React 状态，由 App 组织 | 跨页面传递器材、目标和示例会话 |
| 持久化 | localStorage | 保存档案、课程、器材选择、模拟器状态和示例记录 |
| 测试 | Node 内置测试工具 | 验证规则、状态转换和存储恢复 |
| 自动化发布 | GitHub Actions + GitHub Pages | 测试和构建后发布静态产物 |

当前没有后端目录、数据库、用户鉴权或 AI SDK。检查业务源码未发现 `fetch`、`getUserMedia`、XMLHttpRequest、WebSocket 或 sendBeacon 调用；不能把网页本身的资源加载与 AI 请求混为一谈。

个人图片通过浏览器临时对象 URL 预览。支持 JPG、PNG、WebP，单文件上限 12 MB、像素上限 4000 万；HEIC 需要先转为 JPG。图片在页面切换期间可以保留，刷新后需重选。长期记录仅保存文字判断，不包含照片内容、文件名或临时图片 URL。

存储读取有版本和字段校验，损坏记录会清理或回退；写入失败时显示提示。清除操作只处理本项目已知的存储键，并检查删除结果。

## 5. 已完成与待完成的判断

**当前最适合用于产品流程评审、交互演示，以及基于固定规则的摄影基础练习。** 主流程已经具有连贯性，并为未来接入外部数据做了一部分准备。

已经有价值的工程基础包括：

- 摄影规则、指导会话、器材匹配与页面组件分开组织，便于独立测试。
- 指导结果绑定请求、会话、帧和上下文版本，避免修改目标后旧结果覆盖新状态。
- 支持取消、失败重试和中断恢复，不依赖理想路径才能操作。
- 内置示例和个人照片保持不同来源，个人照片不会套用固定示例点评。
- 兼容旧记录及旧页面地址，已有数据不会因为页面改版直接丢失。

以下仍是后续工作：

| 未完成能力 | 实际还需完成的内容 |
| --- | --- |
| 手机现场取景 | 权限、后置镜头、采样、横竖屏、启停和后台恢复 |
| 真实 AI 摄影指导 | 后端、图像传输、模型调用、输出校验、超时、成本与建议质量验证 |
| 实际机型教学 | 逐台核对说明书、按键、菜单、参数范围和行为 |
| 真实器材推荐 | 真实产品资料、镜头兼容性、价格来源和更新机制 |
| 云端产品能力 | 账号、跨设备记录、图片长期保存、订阅及支付 |
| 实际效果验证 | 实体手机测试、真实外拍、教学迁移及用户重复使用情况 |

代码虽然定义了画面、指导和比较的接口，但当前数据类型仍将来源限定为 `fixture`，页面也直接使用内置提供者。后续接 AI 时需要扩展数据类型和接入方式，同时保留现有状态隔离；并非只填一个密钥就能完成。

## 8. 后续推进重点

依照现有架构和已确认的 0.4 版方向，下一阶段应先完成实体手机上的主流程检查，再接手机摄像头来源，然后接真实 AI 后端。真实机型与器材资料可在内容核实后逐项扩展。

这一顺序能分别回答三个问题：界面在现场是否好用、手机能否稳定提供画面、建议能否帮助用户拍出更符合目标的照片。当前代码已能支持前一阶段的流程评审，后两个问题仍需要新的实现和实测证据。
