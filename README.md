# 取景 FRAME · 手机摄影导师框架

当前版本 **0.4.0**。产品以手机观察现场为基础，用户最终用手机或相机拍摄。本阶段先完成不依赖摄像头和 AI 的交互框架，指导内容使用明确标注的原创内置示例。

**课程作业仓库：[RuohanLiu3/photo-mentor](https://github.com/RuohanLiu3/photo-mentor)**。

**网站发布地址：[取景 FRAME](https://ruohanliu3.github.io/photo-mentor/)**。GitHub Pages 部署成功后，手机或电脑浏览器均可直接打开，无需启动本地服务器。部署结果见仓库的 Actions 页面。

## 可以体验什么

| 模块 | 已实现 |
| --- | --- |
| 手机导航 | 首页、拍摄、学习、器材、我的；兼容旧 hash 路由 |
| 拍摄体验 | 设备与目标准备、三组示例、一个主要动作、现场限制、参考卡、调整选择、前后对比、偏好与原因 |
| 异步流程 | 延迟的内置数据来源、取消、失败重试、无法判断、无变化；上下文版本与旧响应隔离 |
| 器材探索 | 需求问卷、四套虚构教学组合、本地匹配理由、详情、最多三套比较、收藏与加入我的器材 |
| 机型模拟器 | 机型窗口、完整通用配置、正背顶三面热点、M/A/S 参数联动、自由体验和三类任务；未覆盖型号可记录 |
| 学习 | 原有曝光、景深、构图三课，滑杆、刻度、微调、规则反馈、提示及进度恢复 |
| 我的 | 常用设备档案、收藏、已有套装、课程提交、拍摄判断、继续体验、清除本机数据 |
| 个人图片 | 选择两张本机图片、手动并排或切换比较、同步缩放和观察位置、保存文字判断；不套用示例建议 |

器材金额仅为预算筛选演示，不是真实商品现价。通用模拟器不声称精确复现任何实际型号或镜头画质。当前没有摄像头调用、相机连接、AI 服务、硬件、账号、支付或云同步。

## 本地运行与检查

项目要求 Node.js 22.12 及以上，CI 配置使用 Node.js 24。

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。开发服务器只监听本机。

```sh
npm test
npm run build
npm run format:check
npm run preview
```

`build` 包括 TypeScript 检查，产物位于 `dist/`。开发环境的拍摄页提供折叠的“开发验收场景”，可检查延迟、失败、无可靠建议及无变化；生产构建隐藏该入口。

## 主要代码

- `src/App.tsx`：路由、共享状态、跨模块传递与个人图片生命周期。
- `src/coaching.ts`：帧、指导、比较接口及带版本的示例会话；`src/components/coach/FixtureScene.tsx` 是对应图示。
- `src/gear.ts`：教学套装、需求匹配与对比规则。
- `src/simulator.ts`：机型配置、热点、曝光模式与任务状态。
- `src/domain.ts`、`src/learning.ts`：原有教学规则与课程进度。
- `src/storage.ts`、`src/framework.ts`、`src/hooks/useLocalState.ts`：兼容旧记录的存储、档案、路由与保存失败提示。
- `src/pages/`：独立页面；`tests/`：行为与数据恢复测试。

## 本机数据

示例进度、器材探索、模拟练习和档案分别保存于版本化的本机存储，旧 `frame` 练习记录兼容读取。收藏不会自动成为已有器材；临时进入模拟或拍摄不会静默修改常用档案。

个人照片只保留临时预览对象，跨页面可继续查看，刷新后需要重新选择；照片内容、文件名和预览 URL 不写入文字记录。图片不发送给模型或应用服务端。存储不可用时显示提示，当前体验仍可继续。

## 后续顺序

1. 接入手机摄像头来源，单独验证权限、后置镜头、采样、横竖屏、启停与后台恢复。
2. 接入真实 AI 后端，验证上传、超时、失败、费用、版本绑定及实际建议质量。模型密钥保留在服务端。
3. 依据官方说明书逐台补齐真实机型；核实器材规格、卡口、地区价格与更新时间。
4. 在实际手机和现场场景中检验操作与改善效果，再考虑扩大能力。
